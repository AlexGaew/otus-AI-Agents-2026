# ТЗ: Telegram-бот «входящие»

Дата: 2026-10-12

## 1. Цель

Личный Telegram-бот, в который я кидаю заметки и ссылки. Бот предлагает теги, хранит записи, находит их по словам и присылает ежедневный дайджест.

Побочная цель: пройти весь путь проекта вместе с кодинг-агентом, включая настройку правил (`CLAUDE.md`), хуков и скиллов.

## 2. Пользователь и доступ

- Один пользователь, я.
- Доступ по белому списку Telegram ID. Остальным бот не отвечает.

## 3. Функциональные требования

| # | Требование |
|---|---|
| F1 | Приём текстовой заметки: сохраняется текст, дата и время |
| F2 | Приём ссылки: бот вытягивает заголовок и краткое содержание страницы и сохраняет вместе со ссылкой |
| F3 | Теги: после сохранения бот предлагает теги (модель), я подтверждаю или правлю кнопками |
| F4 | Поиск: команда с поисковым запросом возвращает записи по совпадению слов в тексте, заголовке и тегах |
| F5 | Дайджест: каждое утро бот присылает список того, что я добавил за предыдущий день, сгруппированный по тегам |

## 4. Вне рамок первой версии

Задачи со сроком и напоминания, голосовые сообщения, картинки и файлы, смысловой поиск, мониторинг цен и объявлений, рыбалка, несколько пользователей.

## 5. Технические требования

| Область | Решение |
|---|---|
| Язык и фреймворк | Java 21, Spring Boot |
| Telegram | Библиотека TelegramBots для Java |
| Хранилище | PostgreSQL в Docker |
| Планировщик | Spring `@Scheduled` для дайджеста |
| Модель | Дешёвая облачная языковая модель по API, только для тегов и краткого содержания |
| Интерфейс | Только Telegram, отдельного фронтенда нет |
| Запуск | Локально для разработки, затем на VPS в Docker |

## 6. Нефункциональные требования

- Секреты (токен бота, ключ модели, пароль БД) только в переменных окружения, не в репозитории.
- В бота не отправляется ничего чувствительного: пароли, личные данные, рабочая информация. Это правило использования, не техническая защита.
- Бот работает без моего компьютера. Перезапуск не теряет данные.

## 7. Критерий готовности MVP

Я отправляю в бота заметку и ссылку, подтверждаю предложенные теги, нахожу их поиском по слову, и на следующее утро приходит дайджест. Всё работает на VPS.

## 8. Порядок работы

1. Папка проекта, `CLAUDE.md`, первичные правила для агента.
2. Скелет: Spring Boot, подключение к PostgreSQL в Docker, бот отвечает только мне.
3. F1 и F2: сохранение заметок и ссылок.
4. F3: теги через модель с подтверждением кнопками.
5. F4: поиск.
6. F5: дайджест по расписанию.
7. Деплой на VPS.

Хуки и скиллы настраиваем по ходу, когда в них появляется реальная потребность.
