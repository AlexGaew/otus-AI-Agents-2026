# review-step

Проверь изменения текущей ветки относительно `main` на соответствие шагу ТЗ: $ARGUMENTS

Если аргумент не указан, определи шаг по изменениям и назови его в начале отчёта.

## Порядок

1. Прочитай `ТЗ-telegram-bot.md`: требование шага (раздел 3), технические и нефункциональные требования (разделы 5 и 6), «Вне рамок» (раздел 4).
2. Посмотри изменения: `git diff main...HEAD` и `git log main..HEAD`.
3. Запусти юнит-тесты (команда в `AGENTS.md`). Если команда ещё TODO, так и напиши, не выдумывай.
4. Проверь по списку ниже и выдай отчёт.

## Чек-лист

- **Соответствие ТЗ**: требование шага реализовано целиком; нет функциональности из раздела «Вне рамок».
- **Доступ**: проверка белого списка Telegram ID стоит на входе любого апдейта, посторонним бот не отвечает.
- **Секреты**: токен бота, ключ модели и пароль БД не попали в код, конфиги, compose-файлы и историю коммитов.
- **TDD**: у нового поведения есть тесты, тесты проходят, их не ослабляли ради прохождения.
- **Устойчивость**: сбой LLM или страницы по ссылке не теряет запись пользователя; данные переживают перезапуск.
- **Стек**: нет новых зависимостей и технологий вне ТЗ без согласования.

## Формат отчёта

Три раздела: «Блокирует слияние», «Стоит исправить», «Замечания». Для каждого пункта: файл и строка, суть, как исправить. Если проблем нет, напиши это прямо. Ничего не исправляй сам, только сообщай.
